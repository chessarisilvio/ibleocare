Lo Stack Software

MQTT Broker (Mosquitto)
Open Source Scalabile Standard IoT

Il broker MQTT Mosquitto è il cuore del sistema di messaggistica. Gestisce centinaia di dispositivi connessi simultaneamente con overhead minimo. Il protocollo QoS 1 garantisce la consegna affidabile dei messaggi anche in caso di connessione instabile tipica dei campi agricoli remoti.

Backend Node.js + Express
REST API WebSocket Event-Driven

Il server applicativo è costruito su Node.js con Express.js. L'architettura event-driven di Node.js è perfetta per l'IoT: gestisce migliaia di connessioni WebSocket simultanée senza bloccare il thread. Le API REST permettono l'integrazione con app mobile di terze parti.

Database PostgreSQL
ACID Scalabile Open Source

PostgreSQL archivia tutte le letture dei sensori con timestamp preciso al millisecondo. Le query ottimizzate con indici su timestamp e device_id permettono di restituire 30 giorni di dati storici in meno di 50ms. Supporto nativo per dati JSON per flessibilità futura.

Dashboard con Chart.js
Real-time Responsive Grafici interattivi

La dashboard web utilizza Chart.js per visualizzazioni real-time e storiche. Grafici a linea per l'andamento di umidità e temperatura, grafici a barre per il confronto settimanale, gauge per i valori in tempo reale. Tutto aggiornato via WebSocket senza refresh della pagina.

Le Nostre Decisioni Tecniche

MQTT è progettato specificamente per l'IoT: consumo dati 100x minore di HTTP, latenza inferiore al secondo, supporto nativo per connessioni instabili tipiche dei campi agricoli. Un messaggio MQTT con i dati del sensore occupa meno di 1 KB contro i 5-20 KB di una richiesta HTTP con header.

I sensori resistivi si ossidano in 3-6 mesi nel terreno umido, rendendo le letture progressivamente inaffidabili fino all'inutilizzabilità. I sensori capacitivi non hanno parti metalliche esposte all'elettrolisi: durano anni senza alcuna manutenzione, riducendo drasticamente i costi operativi.

L'architettura asincrona e non-bloccante di Node.js gestisce migliaia di connessioni WebSocket simultanée, ideale per una dashboard real-time multi-utente. Python con un server WSGI tradizionale aprirebbe un thread per ogni connessione, diventando un collo di bottiglia al crescere degli utenti.

I dati dei sensori hanno una struttura altamente regolare (timestamp, device_id, valore): un database relazionale con indici ottimizzati su queste colonne è più efficiente di un NoSQL per query temporali. PostgreSQL restituisce 30 giorni di letture in <50ms grazie agli indici B-tree su timestamp.

Il Raspberry Pi ha costi, consumi e dimensioni 10x maggiori. L'ESP32-S3 esegue tutto il firmware necessario con 240MHz, WiFi e BLE integrati in un chip da 21x17mm al costo di circa 5€. Per l'edge IoT embedded, è la scelta industriale corretta.
